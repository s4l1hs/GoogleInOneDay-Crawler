For production deployment, keep the filesystem sharding model as a fast local write-ahead layer, then add a background compaction service that continuously merges JSONL shards into immutable segment snapshots. This preserves fast append performance for crawlers while preventing shard bloat and reducing query scan costs. Add segment manifests, periodic snapshot rotation, and retention policies so search can read stable segments while new data is still being appended.

To scale crawling and query throughput, split crawler workers by domain hash partitions and enforce per-host politeness/rate budgets centrally. Place a query service in front of segment readers with in-memory posting caches for hot terms, and add operational metrics for queue occupancy, checkpoint lag, append errors, and p95 query latency. Replicate checkpoint files (frontier + visited) to durable storage so interrupted workers can resume with minimal loss.
